## V81에서 실제 반영한 내부 연결
1. 총무과의 기존 **전체 발주서 발송** 버튼: 화면 그대로 두고 내부에서 `common/order-transport-v81.js`를 호출. 원래 V72 발주 객체 전체를 공개용 Supabase 인증 클라이언트로 `jinil_orders`에 저장하고 해당 부서를 `jinil_dispatches`에 전송. server 승인이 확인된 건만 기존 로컬 송부 완료 표시. 전송 실패 건은 로컬에 보존. stable order_no와 고유 제약/전송 전 조회로 중복 송부를 방지. 예제(testOnly/demo) 주문은 운영 송부하지 않음.
2. 기존 V72 블록 색/배치는 그대로, `common/order-realtime-v81.js`에서 회원별 `jinil_notifications` 수신, 새 알림 때만 중앙 약 3초 및 우하단 X 알림을 표시. 미읽음 부서 블록에만 동적 녹색 강조; 해당 부서를 열면 `read_at` 기록. 새 고정 메뉴 버튼 없음. OS 푸시 전용 `jinil-push-order-v78` Edge Function 및 기존 자동 발주 트리거는 유지하며 이번 작업에서 변경하지 않음.
3. 기존 블록 배치 저장 함수와 내부 블록 구성 저장 함수에 `common/layout-sync-v81.js`를 연결. Supabase 별도 `jinil_v72_member_layout` 테이블 생성(3개 자기 계정 전용 RLS 정책, Realtime 게시). 로컬 배치를 먼저 유지하며 로컬 배치가 없거나 안전한 최신 원격 시각 비교가 성립할 때만 다른 기기의 배치를 복원. 서버 복원 전 현재 로컬 배치의 별도 백업 생성. 디자인/버튼 추가 없음.
4. `tools/jinil_launch.py` 실행 대상을 V81로 변경. 기존 V72~V80, V79 간이 발주 UI 파일은 삭제/덮어쓰기하지 않음.

## 후속 보완 2026-11-24 · 부서별 발주 원본 화면 서버 조회
- 기존 V72 발주 목록 화면 `renderTestModule`, `renderGeneralOrders`의 HTML/CSS/버튼 자체는 보존했다.
- `common/order-transport-v81.js`에 Supabase 부서별 `jinil_dispatches` 조회를 추가하고, 기존 V72의 `testData()`가 로컬 데이터와 서버 수신 데이터를 읽기 시점에만 합치도록 변경했다. 서버 수신 데이터는 `__jinilRemoteOnly`로 구분하며 기존 `saveTestData()`로 로컬에 저장하지 않도록 제거한다.
- Supabase 로그인 후 실시간 채널 및 30초 재조회. 리스트 화면에서 입력 중/모달 사용 중이면 강제 다시 그리기를 피한다.
- 원래 '완료' 버튼이 서버 발주를 처리하는 경우 원래 화면 그대로 서버의 `대기→확인→완료` 상태 변환을 거친다. 서버 미확인 결과를 성공으로 표시하지 않는다. 원래 로컬 발주 버튼 처리는 이전 동작 유지.
- 서버 완료 취소/발주 취소는 DB 기존 guard가 지원하지 않는다. 원본 버튼 자체는 보존하지만 서버 발주에서는 오류를 안내하고 거짓 변경하지 않도록 했다. 따라서 해당 업무의 완전한 양방향 동기화를 달성했다고 보고하지 않는다.
- 모의 코드 테스트: 서버 생산부 대기 기록이 V72 목록에 나타나고 원래 발주 번호를 표시함. 원래 로컬 기록 보존, 서버 수신 전용 기록 로컬 저장 방지, 대기→확인→완료 변환, 완료 취소 차단 검증.
- Supabase 실제 SQL 롤백 시험: 슈퍼관리자 발주 생성 → 생산부 송부 → 생산부 권한으로 송부 ID 조회 → 상태 확인 및 완료 → 최종 상태 '완료', 해당 알림 1건 생성 확인. 트랜잭션 롤백, 테스트 데이터 미보존. 생산부가 총무부 발주 원본 ID를 직접 조회하지 못하는 RLS도 관찰됨.
