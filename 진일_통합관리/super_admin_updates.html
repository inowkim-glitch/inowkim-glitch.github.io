JINIL · 슈퍼관리자 업데이트 센터

V72 개발 브랜치 · 등록 → 격리 테스트 → 승인 → 배포 대상 지정 → 복구

운영 주의 이 화면은 V72 작업용 업데이트 관리 기능입니다. '배포 대상 지정'은 Supabase의 버전 포인터를 변경합니다. 기존 29개 HTML 파일이나 GitHub Pages 운영 화면을 직접 교체하지 않습니다. 실제 배포 자동화는 별도 연결·검증 후 사용해야 합니다.

HTML 미리보기는 격리된 iframe에서 실행됩니다. 외부 네트워크를 사용하는 코드가 포함될 수 있으므로 신뢰할 수 있는 파일만 올리세요.

1. 로그인 및 슈퍼관리자 권한 확인

로그인이 필요합니다.

2. 기타블록 폴더 등록

이름을 등록하면 기타블록에 새 경로가 만들어지고, 슈퍼관리자 메인 목록에 흐릿하게 표시됩니다. HTML을 넣기 전에는 테스트 대기 상태입니다.

이 화면의 폴더 등록은 Supabase 블록 등록부에 경로를 생성하는 기능입니다. GitHub 개발 브랜치에 실제 폴더 및 HTML 파일을 생성하려면 별도의 GitHub 연동 또는 ChatGPT를 통한 반영이 필요합니다.

3. HTML 파일 불러오기 및 버전 등록

파일 최대 750KB. 동일 블록은 최신 3개 버전을 보관합니다. 4번째 등록 시 가장 오래된 비운영 버전을 정리하고, 현재 운영 버전이 가장 오래된 경우 등록을 안전하게 차단합니다. 기존 운영 HTML 파일은 자동 덮어쓰지 않습니다.

4. 불러온 버전 확인·테스트·배포 대상 지정·복구

미리보기 후 '테스트 통과'를 선택하면 배포 대상으로 지정할 수 있습니다. 이전에 테스트를 통과한 버전을 다시 지정하면 복구 포인터로 활용할 수 있습니다.
