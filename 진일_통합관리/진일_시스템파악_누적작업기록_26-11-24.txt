[6. 회사 실제 업무 기본 흐름 | 2026-11-24 사용자 직접 설명 | 설계 기준]
기록 성격: 아래는 사용자가 회사 운영 방식을 직접 설명한 내용이며, V75 구현 완료나 Supabase 자동 연동을 뜻하지 않는다. 이전에 보조자가 임의로 제시했던 '발주서 접수 → 발주 내용 확인 → 재고 확인 → ...' 흐름으로 대체하지 말 것.

A. 총무과의 고객 발주 배분
- 고객이 발주하면 총무과가 생산부, 가공부, 테프론부 세 파트로 해당 발주서를 작성하여 보낸다.
- 발주서는 한 건씩 작성해 전송해도 되고, 여러 건을 누적하여 전송해도 된다.
- 발주를 받은 각 파트의 주문은 처음에 '대기' 상태로 존재한다.

B. 세 파트의 수주 확인 및 진행 상태 공유
- 생산부는 '생산부 확인', 가공부는 '가공부 확인', 테프론부는 '테프론 확인'을 누른다.
- 각 부서가 확인을 누르는 즉시 총무과에서 확인 상태를 실시간으로 볼 수 있어야 한다.
- 확인 후 각 부서의 작업이 진행된다.
- 해당 부서가 작업을 마치고 '완료'를 누르면 총무과에서 완료 상태를 실시간으로 확인할 수 있어야 한다.
- 부서별 확인과 완료는 각 발주 내역과 연결되어 추적되어야 한다.

C. 가공부의 소재 요청은 별도 필수 경로
- 생산부와 테프론부는 소재 자체를 생산하는 부서이고, 가공부는 그 소재를 받아 가공하는 부서다.
- 따라서 가공부는 가공에 필요한 소재를 해당 공급 부서에 요청해야 한다.
- 요청처 1: 생산부. 생산부에서 생산되는 소재를 요청한다.
- 요청처 2: 테프론부. 테프론부에서 생산되는 소재를 요청한다.
- 요청처 3: 총무과. 회사에서 직접 생산하지 않는 '사급 소재'를 주문/조달해 달라고 요청한다.
- 부서 간 거리가 있으므로 요청 소재는 실제로 이동해 가공부로 전달된다.
- 소재를 가져온 사람이 전달 '완료'를 누르면 가공부는 소재가 도착했음을 확인하고 가공 작업을 시작할 수 있다.
- 가공부가 가공을 마친 뒤 '가공 완료'를 누르면 총무과에서 작업 완료를 확인한다.
- 소재 요청 완료/전달 완료와 가공 작업 완료는 서로 다른 사건으로 구분한다.

D. 총무과 납기 관리와 출하 단계
- 각 부서의 작업 완료 상태를 총무과가 확인한 뒤 예상 납기일과 실제 납품 예정 일정을 살펴 납품일을 정한다.
- 서울로 발송하는 물량은 발송일 또는 발송 예정일을 정한다. 서울에서 '이때 발송해 주세요'라고 발송 예정일을 지정할 수 있다.
- 사용자 설명상 발송은 보통 작업 완료 당일에 이루어진다. 다만 완료일과 발송 예정일/납품일은 구분한다.
- 필요한 작업이 모두 완료되면 '출하 대기'로 넘어가고 영업부가 출하한다.
- 출하 방법은 직접 납품, 화물, 서울행 이동 등으로 나뉜다.
- 납품서에 기재된 예정일과 납품 날짜를 확인하면서 출하와 납품을 진행한다.

E. 핵심 상태 흐름(설계 도출, 용어는 사용자 설명 우선)
고객 발주 → 총무과 발주서 작성 및 세 파트별 전송(한 건 또는 누적 전송) → 해당 파트 '대기' → 해당 파트 '확인' → 작업 진행 → 해당 파트 '완료' → 총무과 실시간 확인 → 납기·발송 일정 조정 → 출하 대기 → 영업부 출하 → 직접 납품/화물/서울행.
가공부에 한해 별도 선행 경로: 가공부 소재 요청 → 생산부/테프론부/총무과 조달·이동 → 가져온 사람의 전달 완료 → 가공부 소재 도착 확인 → 가공 진행 → 가공 완료 → 총무과에 완료 상태 공유.

F. 추후 구현 시 누락 방지 조건
- 발주 건과 파트별 담당·상태 및 확인/완료 시각의 연계
- 총무과 실시간 진행 상태 확인
- 가공 소재의 유형(생산/테프론/사급)별 요청처 구분
- 소재 전달 완료 버튼의 수행자와 가공부 입고 확인 단계의 분리
- 작업 완료, 예상 납기일, 납품 예정일, 서울 발송 예정일, 실제 발송/출하 및 납품 일자의 분리
- 영업부 출하 담당 역할과 배송 경로 구분
- 총무과, 생산부, 가공부, 테프론부, 영업부의 담당 기능과 접근 권한 정합성 확인
